Welcome to Environmental Computing 👋

The goal of Environmental Computing is to provide accessible coding and statistical tutorials to R users. If you would like to learn more about this site, click here.

This repository uses Quarto to build and maintain the website as a Quarto book. Below are important details to orientate you to the behind-the-scenes of this website.

Installation of Quarto

Download and install Quarto from https://quarto.org/docs/get-started/.

To preview the site locally from R, you can also use the quarto R package:

install.packages("quarto")

Install R dependencies

All R packages used across tutorials are listed in the DESCRIPTION file under Imports. Please make sure dependencies are listed in alphabetical order and keep this file up to date as the site grows.

To install all dependencies:

remotes::install_deps()

Structure of the major directories

EnvironmentalComputing/
├── _quarto.yml         # Book configuration and chapter order
├── index.qmd           # Home page (must stay at root)
├── content2/           # All tutorial content, organised by section
│   ├── big-picture/
│   ├── basics/
│   ├── data-literacy/
│   ├── data-visualisation/
│   ├── essential-maths/
│   ├── statistical-methods/
│   ├── dynamic-systems/
│   └── coding-skills/
├── _book/              # Rendered output (do not edit manually)
└── static/             # Static assets (images, etc.)
  • _quarto.yml controls the book title, chapter order, and HTML theme.
  • content2/ is where you will do most of your work. Each section is a subfolder, and each page is a .qmd file within it.
  • _book/ is generated automatically by Quarto — do not edit files here directly.

Name and code style conventions

Please follow these conventions when creating new files and folders:

  • lowercase names
  • use - hyphens to join separate words e.g. meta-analysis
  • keep folder names concise (3 words or fewer)
  • use commonly used abbreviations e.g. glms instead of generalised-linear-models

Use the styler package to format R code within .qmd files:

# An example
styler::style_file("content2/coding-skills/functions.qmd")

Anatomy of a page

Each tutorial is a .qmd file inside the relevant section folder under content2/. The YAML header of each .qmd should include at minimum a title:

---
title: "Title of Your Tutorial"
---

Page order is controlled by the chapters: list in _quarto.yml, not by a weight: field. To change the order of pages, edit _quarto.yml directly.

Working with git

The recommended workflow:

  1. PULL down remote changes at the beginning of your work session.
  2. Proceed to work on the .qmd files.
  3. STAGE your changes.
  4. COMMIT your changes with an informative message — group related changes in a single commit.
  5. PUSH your committed changes.

Note: Should a merge conflict arise, reach out to one of the maintainers and we can help.

Creating a new page

  1. Decide which section the new page belongs to (e.g. coding-skills/, data-visualisation/).
  2. Create a new .qmd file in the relevant subfolder under content2/, following naming conventions above.
  3. Add a YAML header with at minimum a title:.
  4. Add the new file path to the chapters: list in _quarto.yml in the desired position.
  5. Write your tutorial content.

Building and previewing the site

To render the entire book:

quarto::quarto_render()

To preview the site with live reloading:

quarto::quarto_preview()

Or equivalently from the terminal:

quarto render
quarto preview
